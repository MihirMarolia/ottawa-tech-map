# Local Supabase verification

Ticket 05 is local and project-neutral. It does not link to or mutate a remote Supabase project.

## Prerequisites

- Docker Desktop with the Linux container engine running
- Node.js and npm
- network access the first time the pinned Supabase CLI and Docker images are downloaded

The supported workflow uses Supabase CLI 2.109.1 through `npx`; it is not added to application dependencies.

## Commands

Start the local stack:

```bash
npm run db:start
```

Run the complete database proof:

```bash
npm run db:verify
```

The verification command:

1. rebuilds the local database from empty;
2. applies every ordered migration;
3. runs pgTAP schema, constraint, privilege, RLS-facing, and append-only tests;
4. runs the application service through the local Supabase RPC and proves created, replayed, queried Evidence, and technical-recovery behaviour;
5. rebuilds the database;
6. runs eight genuine concurrent PostgreSQL ingestion attempts;
7. proves one created outcome and seven already-processed outcomes;
8. rebuilds the database again;
9. reapplies all migrations and reruns the schema smoke suite.

Run individual stages with:

```bash
npm run db:reset
npm run db:test:schema
npm run db:test:concurrency
npm run db:test:application
```

Local Supabase uses shared development-only credentials generated by the CLI. Never copy them into repository files, browser configuration, logs, fixtures, or documentation. The application integration harness reads the ephemeral local service-role credential directly from `supabase status`, passes it only to the test process, and does not print or persist it.

## Testing lifecycle

- Unit tests continue to use in-memory repositories.
- Ordinary database assertions run inside a rolled-back pgTAP transaction.
- The concurrency proof commits uniquely identified rows and relies on the following database rebuild for cleanup.
- Application integration tests seed only the existing Company required by the test, then exercise persistence and Evidence queries exclusively through controlled RPCs.
- Migration reproducibility is proven by the second reset and test pass.
- Remote linking, deployment, backups, and environment promotion remain deferred.
